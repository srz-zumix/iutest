Failure signal handler compatibility

The boolean install_failure_signal_handler flag defaults to false. Use IUTEST_FLAG_GET/SET(install_failure_signal_handler) or, with the gtest switch header, GTEST_FLAG_GET/SET(install_failure_signal_handler). Native per-test flag saving/restoration includes this flag. Changing the flag does not itself install or uninstall a handler.

Native iutest stores the preference but does not install a diagnostic handler, on any platform. This matches GoogleTest v1.18.0 without Abseil: existing signal dispositions are untouched even when the flag is true. No async-signal-unsafe stack tracing or exception recovery is attempted. This also keeps old compilers and platforms without signal APIs supported.

Native environment variables are read at framework initialization: IUTEST_INSTALL_FAILURE_SIGNAL_HANDLER takes precedence over GTEST_INSTALL_FAILURE_SIGNAL_HANDLER. Unset means false; exactly "0" means false; every other value (including empty, "false", and "00") means true. In IUTEST_USE_GTEST mode only the upstream GTEST_ variable is used.

The ordinary upstream parser omits this flag from its explicit allowlist. Unrecognized –gtest_ options remain in argv and request help. Native –iutest_install_failure_signal_handler behaves the same way; neither spelling is a native command-line or flagfile setting.

To obtain diagnostics using the upstream implementation, build GoogleTest v1.18.0 with GTEST_HAS_ABSL and its required Abseil/RE2 dependencies, select IUTEST_USE_GTEST, and enable the flag via the environment before startup or the flag API before the first IUTEST_INIT. Installation occurs once in PostFlagParsingInit (or at the first run if initialization was omitted). A later flag change or per-test flag restoration does not undo installation. The ordinary GoogleTest v1.18.0 flag saver omits this flag; unlike native iutest, that upstream configuration requires callers to restore its value. Upstream uses default absl::FailureSignalHandlerOptions: on supported POSIX platforms it uses sigaction; Windows uses signal and has no alternate stack. Exact platform support depends on the linked Abseil build. The handler emits diagnostics and terminates; it does not recover or add death-test support.

IMPORTANT: upstream's default options do not chain to an existing handler. If an application already owns signal handling, leave this flag false. A native application needing diagnostics can explicitly install its chosen handler before IUTEST_INIT, with chaining/lifetime options it controls; iutest will not replace it.

Reference implementation: https://github.com/google/googletest/blob/v1.18.0/googletest/src/gtest.cc (flag definition, PostFlagParsingInit, ParseGoogleTestFlag, ParseGoogleTestFlagsOnly), and https://github.com/google/googletest/blob/v1.18.0/googletest/src/gtest-port.cc (BoolFromGTestEnv).
